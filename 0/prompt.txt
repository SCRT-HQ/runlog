## Findings

### Critical

**1. Concurrent renewal burns the rotating refresh token — `streamdeck/src/session.ts:70-84`**

`bearer()` reads the session off disk, and if `needsRenewal` is true calls `renew()` with no guard. Two callers can be in flight at once: `openWire.open()` (`socket.ts:86`) and `fetchSnapshot()` (`socket.ts:59`), and `fetchSnapshot` fires on every `changed` ring. Two rings in the same turn — a roll that publishes twice — both read the same `refreshToken` and both POST it. WorkOS rotates on every renewal, so the second is refused. In `fetchSnapshot` that silently drops a snapshot (recoverable). In `open()` the refusal returns `null`, which dispatches `{ t: "session", state: "expired" }` (`socket.ts:93`) and `reduce` resets to `initial()` — the whole deck goes to **Sign in again** while the session is in fact fine. Where the issuer treats refresh-token reuse as a compromise signal, it becomes a real sign-out mid-stream.

The 60-second `RENEW_MARGIN_MS` against a 1-hour token means this window opens once an hour of active play. Smallest fix — share the in-flight promise:

```ts
let renewing: Promise&lt;string | null&gt; | null = null;
export async function bearer(_account: Account): Promise&lt;string | null&gt; {
  const session = loadSession();
  if (!session) return null;
  if (!needsRenewal(session, Date.now())) return session.accessToken;
  renewing ??= renew(session)
    .then((r) =&gt; (writeSession(dir(), r), r.accessToken))
    .catch(() =&gt; null)
    .finally(() =&gt; { renewing = null; });
  return renewing;
}
```

`session.test.ts:49` already proves rotation is written back; add a case that fires two `bearer()` calls and asserts `fetch` was called once.

**2. The branch does not carry the page half it presses — needs `origin/main` merged in**

`streamdeck/src/actions/setup.ts:22` sends `{ press: "answer", answer: { setup: id } }`, and `state.ts:26` declares `setups` on the mirrored `Offer`. On this branch, `apps/web/src/run/offer.ts` has no `setups` field and `takePress.ts` has no `setup` branch — an Apply setup press would fall through to the `declareSubject` check and come back *"The run is not asking for that."* On `e4c50ac` both exist (`offer.ts:26`, `takePress.ts:89-94`). Merge `origin/main` before opening so CI runs against the real pair. The merge itself is clean.

### Important

**3. `redrawAll` swallows nothing and catches nothing — `streamdeck/src/actions/base.ts:100-102`**

```ts
for (const a of this.actions) void a.getSettings&lt;S&gt;().then((s) =&gt; this.draw(a, s));
```

No `.catch`. `draw()` guards only the key branch (`base.ts:81-88`); `this.face(...)` at line 73 and `await action.setFeedback(feedback)` at line 96 are both unguarded, and `face()` reads a snapshot cast `as never` straight off the wire (`socket.ts:65`) with no validation. The SDK installs `process.once("uncaughtException")` (`dist/plugin/logging/index.js:27`) — `once`, so the first rejection is logged and the second takes the plugin down. Add `.catch((e) =&gt; streamDeck.logger.error(...))` on line 101 and move the dial branch inside the existing try.

**4. Every inspector depends on a third-party CDN at load — all eight `ui/*.html`, e.g. `press.html:6`**

`&lt;script src="https://sdpi-components.dev/releases/v4/sdpi-components.js"&gt;`, with no `integrity` and no version beyond `v4`. Offline, or if that host is down, `const { streamDeckClient } = SDPIComponents;` throws before anything renders — the account block, the run picker, the field picker and the setup picker are all dead, so the streamer cannot even sign in. For a Marketplace plugin, vendor the file into `ui/` (it is one JS file, no build) or at minimum pin an exact release with `integrity` + `crossorigin`.
