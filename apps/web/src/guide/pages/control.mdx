# Making a result happen in the game

The control protocol lets a program apply a result in a game.

A tool running beside the game, on the same machine, can hold the socket open the way a widget does, and do what a result says: apply the status effect, switch the restriction on, take it off when the unit closes. The tool can apply the result directly in the game.

The tool is optional. A pack with control rules also works without one; with a tool attached, the result can be applied automatically.

**The game goes offline; the machine does not.** A tool that reaches into a game's memory is against the terms of service of every game that has any, and doing it while the game is online is how accounts get banned. The PC itself stays online, since that is how the run reaches it. In Tarnished Tool, the **Launch Game** button starts Elden Ring the right way.

## What you need

A tool that speaks the control protocol. Today that means a build of **Tarnished Tool** with a Control tab, for Elden Ring. The protocol is not ours and not its: anything that can hold a WebSocket open can speak it, and [the stream API](https://github.com/SCRT-HQ/runlog/blob/main/docs/stream-api.md) says how.

## Setting it up

1. In the run, open **Settings → Stream**.
2. Under **Chat**, make a **watch key** if you have not. That key is what lets a tool read this run.
3. Under **Control**, copy the address and paste it into the tool, with your watch key where the address says to put it.
4. Press Connect in the tool. It says what it is and what it can do; the run answers with its terms, if it has any.

Where more than one person is playing, everyone else attaches on the run's **live link** instead of a watch key, which they already have.

For a roster run, the Control section provides a separate address containing each racer's name. Give each racer their own address. A rule addressed to one of those names reaches only that machine; a rule addressed to nobody reaches all of them, which is how one warp lands on four games at the same moment.

## Writing the rules

**Settings → Stream → Control** is where a run says what a result means.

A rule matches one result, or anything carrying a tag, or anything from a whole table, and says what to do about it. The panel knows the pack and the tool, so it will tell you when a rule can never fire, when a number is outside what the tool accepts, and when an operation is one it has never heard of.

Choose an effect duration:

| It lasts               | When to use it                                                    |
| ---------------------- | ----------------------------------------------------------------- |
| Until the run ends     | A term of the run: a restriction that holds throughout.           |
| Until this unit closes | Almost always this. A curse drawn for a region lasts that region. |
| For a while            | Where seconds are genuinely the point.                            |

There is also **the run's terms**: what a tool is set to the moment it attaches, held until the run ends and then put back. The settings that would otherwise be a paragraph in a description and fifteen boxes ticked by hand.

## Taking it back

The tool tracks active effects and reverses them when they expire. An effect ends when its time runs out, when its unit closes, when the run ends, when the connection stays gone, and when the tool closes. What it restores is what you had, not a switch flipped the other way, so a setting you turned on yourself survives a run that borrowed it.

If the tool stops during a run, it restores settings when it starts again and reports that action.

## What the game can say back

The other direction is smaller and optional: a tool can say what happened to it. A death, said by the game, counts as that player's own press of the move the pack calls it ("I died", say), the moment it lands: the tally moves, the log says the game said it, and nobody has to press Accept.

It travels on the socket the tool already holds, so there is nothing more to set up: switch on **Say when I die** in the tool. The run's page has to be open, since that is the device that keeps the log; the tool's log says "Counted." when it landed, and why not when it did not. A move the run is not offering at that moment is refused in the same words a stream deck would hear.

## A pack written for it

**Elden Ring: TarnishedTool** is the one to try. Ten minutes a scene, and each scene draws a curse that happens to the game: you are slower, the dead get back up, night falls. Its profile is in the repository under `packs/profiles`, and **Import** in the Control panel loads it.

The pack also works without an attached tool, as required for every included pack.
