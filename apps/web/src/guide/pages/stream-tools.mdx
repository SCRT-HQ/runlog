# For a chat bot or your own tool

A shared run is readable by anything that can fetch a URL. The live link's token is the key; there is no account or sign-in.

## The numbers

`https://runlog.scrthq.com/api/public/runs/<runId>/metrics?t=<token>`, with the run id and token from the live link, answers with one flat JSON document: the unit, where the run stands, the score in the pack's own words, the last result rolled, standings, counters, resources and clocks, as the owner's device last wrote them. It answers any origin, so a page of your own can read it directly. Read it no more than once every five seconds.

## The bell

A socket at `wss://runlog.scrthq.com/ws?run=<runId>&t=<token>` rings when the run moves, with `{"t":"changed"}`, and carries the table's gestures as they happen: `rolled` with the dice as they land, `outcome`, `award`, `clock`, `counter`, `unit-closed`, `run-ended`, each with its words in `data`. The dice everyone watching sees land, on the live page or in a seat, are the same throw your tool receives.

## Asking the run for something

The one request that goes the other way: `POST https://runlog.scrthq.com/api/public/runs/<runId>/asks?k=<askKey>` with a JSON body of `{ "kind": "roll" }`, to roll the table the run is waiting on, or `{ "kind": "move", "move": "<id>" }`, to take a move the pack offers at any time; add `name` and `via` so the log says who asked and how.

The same four fields may travel in the address instead, as `?k=&kind=&move=&name=&via=`, for a tool that can only fetch a URL. That form always answers `200`, refusals included, so a sub-action that stops on an error status still runs on.

The same address with no `kind` at all is a question instead: it answers with what may be asked for at that moment, `roll` and `moves` by id and label, and a `say` that lists them in the pack's own words. A press may also carry a `ref` of your own, a redemption or message id, and a press whose `ref` has been seen before answers as the first one did rather than pressing twice.

Either way the answer carries `ok` and `say`: one sentence written for a chat line, whether the ask is in or why it is not. The key is made under the run's **Settings** → **Stream** → **Chat**, and is not the live link's token. Whether the table took it comes later, on the socket, as an `asked` gesture. One a name every twenty seconds, thirty a minute for the run.

## The fields, in full

The repository's [stream API](https://github.com/SCRT-HQ/runlog/blob/main/docs/stream-api.md) is the contract, kept beside the code that answers: every field of the document, the socket's messages, and the shape of each gesture.
