# Streaming a run <Plan tier="plus" />

A run on a stream wants its own pieces on screen: the scoreboard beside the camera, the clock in a corner, the race leaderboard across the top. Each of those is a **widget**: one panel of the run on a page of its own, with nothing else on it, that follows the run as it moves. Runlog has no plugin to install; a widget is a web page, and every streaming app can show one.

## The address that works on a stream

A widget reads the run one of two ways, and a streaming app needs the second.

- **From this device.** The plain address reads the run from this browser's own storage, the same log the app plays from. That is what **Open** gives you: a pop-out window on the machine you play on, which needs no account and works offline.
- **By live link.** With a live link shared under **People at the table**, tick **For another machine** and the address carries the link's token; the widget then reads the run from the server. OBS and Streamlabs run a private browser of their own with nothing in its storage, so this is the address they want, whether or not the streaming machine is the one you play on.

Under **Stream** in the run's Settings, each widget has **Open** and **Copy address**. Two more settings travel in the address: a clear background, so your scene shows through, and a size, since a capture is usually smaller than a screen.

- **Scoreboard**: places, points, and marks in a moderated run.
- **Race**: the leaderboard, as each racer's device reports it.
- **Clock**: the unit's stopwatch or timer, large.
- **Step**: the current step, the constraints in play, the latest result.
- **Stats**: where the run stands — the unit, units done, time on the clock, the score.
- **Trackers**: resources and counters, as bars and boxes.
- **Everything, stacked**: the panels above in one column, for a single browser source down the side of a scene. It leaves out what the run has nothing for: a scoreboard with nobody on it, trackers in a pack that has none, the race when the run is not in one.

<Note>The token in a copied address is the live link's key: whoever has it can watch. Keep it out of anything you publish. **Stop sharing** kills it, and every copied address with it.</Note>

## In OBS and Streamlabs

Add a **Browser Source**, paste the address as its URL, give it a width and height, and tick *Shutdown source when not visible*. Streamlabs Desktop's browser source is the same one. On the streamer's own machine a widget re-reads the run every couple of seconds, and at once when a move arrives from another device through sync; by link it holds a socket that rings on every move, with a poll only while the socket is down. The clocks tick from the log's timestamps, so they agree with the app to the tenth. Sizes for each widget, and a line of CSS to recolor one for a scene, are in [the setup guide](https://github.com/SCRT-HQ/runlog/blob/main/docs/streaming-setup.md).

## A dock for the controls

OBS can keep a signed-in page docked beside the preview: **View → Docks → Custom Browser Docks**, with the app's own address. Sign in inside it once and open the run there; the dock is a second device at your table, so the moves you make in it reach your other screens through sync and the dice you throw there are the dice your watchers see land.

## For a chat bot or an automation tool

When the player throws dice, everyone watching sees the same dice land, thrown the same way, on the live page and for a watcher who took a seat: the tray appears in the corner, tumbles, and settles on the values as they were rolled. The same throw reaches a tool of your own.

A shared run is readable by anything that can fetch a URL. `https://runlog.scrthq.com/api/public/runs/<runId>/metrics?t=<token>`, with the run id and token from the live link, answers with one flat JSON document: the unit, where the run stands, the score in the pack's own words, the last result rolled, standings, counters, resources and clocks, as the owner's device last wrote them. A socket at `/ws?run=<runId>&t=<token>` rings when the run moves and carries the dice as they land. A StreamElements custom widget can draw from it; Streamer.bot can hold the socket for a dice alert and fetch the numbers for a `!score` command. The repository's [stream API](https://github.com/SCRT-HQ/runlog/blob/main/docs/stream-api.md) has the fields, and [the setup guide](https://github.com/SCRT-HQ/runlog/blob/main/docs/streaming-setup.md) has the recipes.

<Note>Where plans are switched on, widgets are part of Plus, like hosting a table: a stream is a table with an audience. Where they are not — the preview, a copy you run yourself — they are open to everyone.</Note>
