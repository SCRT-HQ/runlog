# Streamer.bot, Aitum and Lumia

Streamer.bot runs on the streaming machine and can hold a socket to the run, act when it rings, fetch the numbers, and drive OBS. Aitum and Lumia Stream have the same two pieces under their own names (an HTTP request action with JSON parsing, a WebSocket or webhook trigger) at the same addresses and fields.

## A dice alert

Under **Servers/Clients** → **WebSocket Clients**, add one with the address `wss://runlog.scrthq.com/ws?run=<runId>&t=<token>` and auto-reconnect on. Then make an action with the trigger **WebSocket Client** → **Message** for that client.

The message is one JSON string: `{"t":"gesture","kind":"rolled",…}` when dice land and `{"t":"changed",…}` on every move. Parse it (a *Set argument from JSON* sub-action, or two lines of C#) and act only when `kind` is `rolled`. The other kinds (`outcome`, `award`, `clock`, `counter`, `unit-closed`, `run-ended`, and `ask` and `asked` for what chat asked and what became of it) arrive the same way with their words in `data`, so a result's `text` can go to chat, a death counter's `value` on an overlay, and `run-ended` can switch the scene.

Then the usual sub-actions: **OBS** → **Set Source Visibility** to flash a dice overlay, a sound, a chat line such as `Rolled {total} on {label}`. The gesture's `data` carries the dice as thrown, the total, the roll's label and its notation; [the stream API](#guide/stream-tools) has the shape.

## A channel-point redeem that presses

In the run's **Settings** → **Stream** → **Chat**, **Take asks** makes the run's ask key and shows the address, key included. Copy it. Then make an action on the trigger **Twitch** → **Channel Reward** → **Reward Redemption** (Kick has the same trigger under **Kick** → **Channel Reward**) whose sub-action is **Core** → **Network** → **Fetch URL**. Fetch URL sends a `GET` and nothing else, no body and no method to choose, so the whole ask travels in the address:

```
https://runlog.scrthq.com/api/public/runs/<runId>/asks?k=<askKey>
  &kind=move&move=died&name=%userName%&via=channel-points
```

`kind=roll` rolls the table the run is waiting on; `kind=move` with `move=<id>` takes a move, and the Chat section lists the pack's moves by id beside a button that copies the finished address for each. `name` and `via` are for the log, so it says who asked and how. A chat command works the same way with the command's trigger and `via=command`.

## Saying what happened in chat

Set the sub-action's **Variable Name** to `runlog` and turn **Parse result as JSON** on. Every answer carries one sentence written for chat, so a **Twitch** → **Send Message to Channel** of `%runlog.say%` says either `viewer_42 asked for died. The table answers next.` or why it could not be taken: a key that is not the run's, a run that is over, a move id the pack does not have, or `Too quick. viewer_42 can ask again in 11 seconds.` `%runlog.ok%` is `true` or `false` for an action that wants to branch.

The address always answers `200`, refusals included, so the sub-action runs on and the sentence reaches chat instead of the action stopping dead.

Whether the table took it is a separate question, and a later one: under **Wait for me to accept** the ask sits in the Asks panel until you press, and under **Act on it as it lands** the host's device acts as it arrives. Either way the socket carries an `asked` gesture with `accepted` true or false and a reason, so the action on the **WebSocket Client** → **Message** trigger above can say `Chat's forfeit is in` or `No such move right now`.

## Giving the points back

A refused redeem should not cost anything. In the same action, after the fetch, branch on `%runlog.ok%` and add **Twitch** → **Channel Rewards** → **Update Redemption Status** set to **Cancel**, which refunds the points. It only works on a reward Streamer.bot made itself, so create the reward with **Create Reward** on the trigger rather than by hand in the Twitch dashboard.

The key is not the live link's token, on purpose: the token is in every widget address and so in your scene, and a leaked address should let strangers watch, never press. **Stop taking asks** kills the key and leaves the link alone.

## A `!score` command

Make a command action for `!score` whose sub-action is **Core** → **Network** → **Fetch URL** on `https://runlog.scrthq.com/api/public/runs/<runId>/metrics?t=<token>` with *parse as JSON* on and a prefix of your choosing, say `run`. The document's fields become arguments, so a **Twitch** → **Send Message to Channel** of `%run.words.unit% %run.unit% · %run.score.text%` says "Day 4 · 3 days" in the pack's own words. `%run.latest.text%` is the last result rolled, for a `!last` command.
