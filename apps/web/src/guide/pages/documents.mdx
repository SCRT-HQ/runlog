# Documents and the command line

A game on a table comes with paper. Runlog writes it from the pack, so it can never disagree with the rules:

- **Rulebook** — everything in reading order: what you need, the terms, a unit step by step, the modes, every table with every entry, the states, tallies, moves and endings.
- **Quick start** — enough to play the first time, with a pointer to the reference card for the tables.
- **Reference card** — every table in columns, plus a list of the things people forget.
- **Run log sheet** — a printable form to write a run on by hand.
- **Summary** — what the catalog shows: the shape of the game without its rules.

## Where to get them

Press **Documents** wherever a pack is:

- on the **Rules** page of the pack you are in,
- on a pack's row in your **library**,
- under **About** on a catalog card,
- in the **Designer**, for the pack you are writing, with a preview.

Each opens in a drawer beside what you were doing, with the other documents a press away; **Print** opens it as its own page for paper or a PDF, the reference card in columns and the run log as a sheet. The files themselves — PDF, HTML and Markdown to keep or to send — are made in the Designer, where an author is producing them. The PDF is laid out in the browser; nothing is sent anywhere.

## The command line

The same documents, and the rest of a designer's toolkit, come from one package:

```
npx @scrthq/runlog docs my-game.yaml -o dist/docs
npx @scrthq/runlog validate my-game.yaml --strict
npx @scrthq/runlog test my-game.yaml
npx @scrthq/runlog keygen -o my-key.json
npx @scrthq/runlog sign my-game.yaml --key my-key.json
```

`validate` checks a pack's shape and coherence, `test` replays the fixtures it ships with, `sign` and `issue` do what the Designer's Sign panel does, `publish` puts a pack in your library on every device.

## Signing in from a terminal <Plan tier="free" />

`npx @scrthq/runlog login` shows a short code and opens your browser to confirm it; from then on `claim` can tie a signing key to your account so the app names you beside what you sign. A machine with nobody at it — a build server publishing a release — uses a key from your profile page instead, set as `RUNLOG_API_KEY`.
