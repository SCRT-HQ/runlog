# The address that works on a stream

A widget reads the run one of two ways, and a streaming app needs the second.

- **From this device.** The plain address reads the run from this browser's storage. That is what **Open** gives you: a pop-out window on the machine you play on, which needs no account, works offline, and could be window-captured.
- **By live link.** With [a live link](#guide/live-link) shared, the address can carry the link's token and the widget reads the run from the server. A browser source needs this: OBS and Streamlabs run a private browser with nothing in its storage, so a plain address there shows "This run is not on this device," however often you refresh.

## Copying the address

Once, for each run you stream:

<Steps>
  <li>In the run, under **People at the table**, choose **Share link** (part of Plus where plans are on).</li>
  <li>Open the run's **Settings**, then **Stream**.</li>
  <li>
    Set **Background** to *Clear* so your scene shows through, or *None* for the words and numbers alone. Under **Theme**, choose **Pin the
    current theme** so the capture keeps the theme you are using now, whatever the streaming machine has chosen. The address then carries
    that theme's colors and fonts. Tick **For another machine** so the address carries the token.
  </li>
  <li>Pick a size (1.25× suits most captures), then **Copy address** on the widget you want.</li>
</Steps>

The address looks like this:

```
https://runlog.scrthq.com/play#widget/clock/01J…?bg=clear&scale=1.25&theme=ember&t=…
```

The `t=` part is the live link's token. Whoever has it can watch the run, so keep the address out of anything you publish. **Stop sharing** kills the token; share again and every copied address needs replacing.

A pinned theme adds `pin=` to the address: the theme's colors and font choices, and no theme name or account. It does not change when you
change the app's theme. **Update pinned theme** makes a new address; one you copied before keeps the old theme until you replace it in
your streaming app.

## A theme that follows this device

Under **Theme**, **Follow this device from anywhere** makes a theme link for this device. The address then carries `ch=` instead of a
pin, and the widget shows whatever look this device applies on any machine: within a few seconds of Apply when the address carries the
live link's token (**For another machine**), and within a minute without it. A System choice goes out as the
light or dark look your computer shows at the time. The link carries colors and fonts only, never a theme's name or your account, and the
address works only once the first look has been sent.

Beside the choice: **Following**, **Not published yet**, **Offline, showing the last look** (widgets keep the last look they were sent), or
**Published from another device**, with **Use this device** to publish from here instead. After a revoke it says **Theme link no longer
works**, with **Make a new link**. On your profile, under **Streaming**, **New link**
makes a fresh address (widgets on the old one show the built-in look until you replace it), and **Revoke** ends the link. A widget may keep
a look it has already shown until it reloads.

A copy of Runlog without the hosted server cannot make theme links; pinned themes work there.

<Note>
  Everything in this part assumes the hosted copy at `runlog.scrthq.com`. A copy you run with your own hosting answers the same way at its
  own address; a static copy has no server, so only the pop-out window works there.
</Note>
